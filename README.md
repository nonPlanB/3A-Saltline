# 几猫3A大作

《几猫》是一款封装在单个 HTML 文件中的浏览器第一人称射击游戏。玩家从港区出发，切断堆场、仓库和码头的三处中继，应对机械飞鸥与机械猎犬，最后抵达撤离艇。港区和武器由 Three.js 绘制，菜单、准星、弹药、任务提示等界面由 HTML 和 CSS 叠加在画布上。

## 运行方式

在支持 WebGL 2 的桌面或移动浏览器中打开 `几猫3A大作.html`，载入后点击 **开始行动**。文件已经内联 Three.js r180、样式和游戏脚本，主启动路径没有引用外部脚本、样式表或模型资源，也无需先执行 npm 安装或构建。Three.js 的 `WebGLRenderer` 使用 WebGL 2。 [Three.js 渲染器文档](https://threejs.org/docs/pages/WebGLRenderer.html)

- **键盘和鼠标**：WASD 移动，鼠标转向，左键开火，右键瞄准，R 换弹，长按 E 切断中继，Space 跳跃，Shift 冲刺，C 或 Ctrl 蹲伏，F 近战，Esc 或 P 暂停。
- **触屏**：左侧滑动控制移动，右侧拖动控制视角，使用屏幕按钮开火、瞄准、换弹和跳跃。接近中继时，使用交互按钮。
- **手柄**：代码轮询采用标准映射的 Gamepad，用双摇杆控制移动与视角，用扳机和按键触发游戏动作。

## HTML 核心结构

下图是浏览器加载时就能从源文件读到的静态结构。`#ui` 在这一阶段还是空容器。

```text
<!doctype html>
html[lang="zh-CN"]
├── head
│   ├── meta[charset="UTF-8"]
│   ├── meta[name="viewport"]
│   ├── title
│   ├── meta[name="claude:viewport-fit-sides"]
│   └── style                     内联样式
└── body
    ├── div#app                    全屏游戏容器
    │   ├── canvas#view[tabindex="0"]  Three.js 绘制目标，可获得焦点
    │   ├── div#ui                 运行时界面的挂载点
    │   └── div#boot               加载遮罩
    │       ├── div.boot-mark
    │       ├── div#boot-msg       当前加载阶段
    │       └── div.boot-bar
    │           └── i#boot-fill    进度条填充
    └── script                    Three.js、游戏模块与启动入口
```

脚本启动后，`#ui` 下会挂载 `.hud`、`.comms`、`.menu` 以及按需创建的 `.touch`。`.menu` 内的 `section[data-s]` 分别对应标题、暂停、失败和任务简报。设置、操作说明、项目介绍共用一个带 `role="dialog"` 的面板，由 `data-tab` 与 `data-pane` 控制切换。加载遮罩和错误提示位于 `#app` 层，启动失败时脚本会动态创建 `#fatal`。

CSS 将 `#view` 与 `#ui` 叠放在同一个视口。`#ui` 默认使用 `pointer-events: none`，菜单和触屏按钮按需接收指针事件，避免纯显示用的 HUD 遮挡游戏输入。

## 工作逻辑

### 1. 启动与模块装配

文档末尾的经典 `<script>` 通过立即执行函数建立作用域，最后调用异步入口 `QC()`。入口读取 URL 参数，创建共享对象 `G`，然后依次把渲染器、场景、摄像机、计时数据、随机数生成器、画质和各子系统挂到 `G` 上。调试时可以通过 `window.__G` 查看这个对象。

1. **初始化渲染和基础服务。** 创建绑定到 `#view` 的 WebGL 渲染器，生成材质，并创建物理、道具工厂与输入系统。
2. **搭建关卡。** 生成集装箱、仓库、码头、起重机等场景内容。关卡模块同时提供玩家出生点、中继坐标、撤离区、敌人出生点和标题镜头路径。场景注册碰撞体后，物理模块构建导航数据。
3. **接入玩法和界面。** 创建粒子特效、音频、玩家、战斗判定、武器、敌人和 HUD，最后创建任务状态机和菜单。状态机通过共享对象调用这些模块。
4. **准备首帧。** `render.onLevelReady()` 尝试生成室内环境反射并预编译着色器。随后加载条推进至 100%，遮罩淡出，渲染器通过 `setAnimationLoop()` 进入主循环。默认先显示标题页，摄像机沿关卡预设路径移动。

每个启动阶段都会更新 `#boot-msg` 和 `#boot-fill`，并让出一次事件循环，使浏览器有机会更新加载界面。渲染器或关卡初始化失败时会进入 `#fatal` 错误路径。音频、粒子、敌人等部分模块有提供相同接口的占位实现，可以在功能受限的情况下继续启动。

### 2. 每帧更新

```text
计算时间步长
  → 读取键盘、鼠标、触屏与手柄输入
  → 更新任务状态
  → 按状态更新玩家、武器和敌人
  → 更新环境与特效，再更新音频和 HUD
  → 渲染画面
  → 清空本帧的新按键记录和视角增量
```

默认情况下，模拟时间步长最多取 `0.05` 秒，避免卡顿后用过大的单帧步长推进移动和任务进度。输入模块分别保存持续按住和本帧刚按下的动作，所以长按开火与单次触发暂停可以共享同一套输入接口。暂停时，玩家、武器、敌人和环境动画停止更新，渲染循环仍继续绘制暂停画面，输入模块也继续监听恢复操作。

### 3. 模块怎样协作

| 模块 | 职责与数据流 |
| --- | --- |
| 输入与玩家 | 输入模块把不同设备归一化为移动向量、视角增量和动作状态。玩家模块读取这些数据，处理移动、碰撞、跳跃、蹲伏、生命值和第一人称摄像机。 |
| 关卡与物理 | 关卡负责可见场景及任务位置。物理模块维护简化的轴对齐包围盒与导航网格，供玩家碰撞、射线查询、视线判断和地面敌人寻路使用。 |
| 武器与战斗 | 武器模块处理弹匣、换弹、后坐力和第一人称枪械动画。开火时，战斗模块先求出场景射线的最近碰撞距离，再在该距离以内检测敌人。这样掩体能挡住射击，命中弱点则按 `2.2` 倍伤害计算。 |
| 敌人与任务 | 敌人模块管理机械飞鸥、机械猎犬的行为与受击。任务状态机读取关卡给出的中继和出生点，在中继切断后按间隔安排增援，并在撤离阶段处理追击。 |
| HUD、特效与音频 | HUD 每帧读取血量、弹药和朝向，也订阅命中、受伤等事件。音频通过 Web Audio 合成声效并使用空间声像。特效模块为枪口、命中点和爆炸生成对应的视觉效果。 |

模块之间既直接调用接口，也通过 `G.events` 发布和订阅事件。例如，`combat.playerShot()` 命中敌人后会发出 `impact` 和 `player:hitEnemy`，HUD 用后者显示命中反馈。切断中继时，状态机更新任务文字和地图标记，同时发出 `objective:done`。HUD 还会把中继和撤离点的三维坐标投影到屏幕上，目标超出视野时把指示标记放到屏幕边缘。

### 4. 任务状态与结算

默认流程是 `title → intro → playing`。战斗期间可以进入 `paused` 并返回 `playing`，玩家死亡后进入 `dead`，完成撤离后进入 `complete`。标题和暂停菜单由状态机控制，失败页和任务简报会在各自的画面过渡后显示。

进入任务后，玩家需靠近中继并在满足距离、高度和朝向条件时持续交互。水平交互范围为 `2.2` 个场景单位，持续操作约 `2.4` 秒可切断一处中继。中断操作会使进度回退。三处全部切断后，HUD 改为指引撤离艇，玩家存活并进入撤离区域即完成任务。结算记录用时、命中率、摧毁数量与重试次数，评级由用时、命中率和是否零重试共同计算。

## 技术特性

### 标准 HTML 作为游戏容器

`<canvas>`、`<style>`、`<script>` 和 `data-*` 属性都是标准 Web 能力。这个文件的特殊之处在于，HTML 主要提供显示表面和界面挂载点，三维对象、碰撞和玩法状态都由 JavaScript 在运行时维护。`claude:viewport-fit-sides` 是额外的自定义元数据，源码中没有读取它的逻辑。页面实际通过 `viewport-fit=cover` 和 CSS `env(safe-area-inset-*)` 处理视口安全区。 [HTML 标准中的 Canvas 元素](https://html.spec.whatwg.org/multipage/canvas.html#the-canvas-element)

### 程序化生成模型、纹理和声音

港区道具、建筑、枪械和敌人由代码构建几何体。纹理生成结合 GPU 着色器和临时二维 Canvas，后者用于绘制标线、文字图集等内容。材质通过 `onBeforeCompile` 在 Three.js 着色器中加入粗糙度、法线和雨水细节。音频模块把合成样本写入 `AudioBuffer`，部分样本分批在启动后生成。这种封装减少了独立素材文件和加载请求，相应的生成成本发生在浏览器端。

### 双摄像机与多通道渲染

世界摄像机绘制港区，`viewCamera` 使用独立视野绘制手部和枪械。高级路径先把世界绘制到 HDR 渲染目标，再绘制武器层并合成画面。按画质和功能开关，管线可以加入湿地面的平面反射、屏幕空间环境光遮蔽、体积光散射、Bloom 和运动模糊。若高级路径在自检或运行期间出错，代码会改用前向渲染，直接绘制世界，再清除深度缓冲并叠加武器层。两条路径都依赖 WebGL 2。 [Three.js 渲染器文档](https://threejs.org/docs/pages/WebGLRenderer.html)

### 画质和浏览器能力适配

初始画质根据触屏设备特征和 GPU 信息选择。高级渲染路径可根据帧耗时调整内部渲染分辨率，持续超出耗时阈值时还可降低画质档位。菜单将画质、灵敏度、反转视角、音量和 FOV 保存到 `localStorage` 的 `saltline.settings.v1` 键。

桌面端通过 Pointer Lock 获取连续鼠标位移。捕获不可用时，代码提供自由鼠标移动、屏幕边缘转向和键盘转向。游戏在已捕获的鼠标被释放或页面切到后台时可进入暂停。 [W3C Pointer Lock 规范](https://w3c.github.io/pointerlock/)

## 调试入口与源码定位
